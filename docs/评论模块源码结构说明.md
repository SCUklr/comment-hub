# 评论模块源码结构说明

本文档用于说明当前评论模块源码的整体结构、接口分布、分库分表路由逻辑、缓存读写逻辑，以及关键流程的伪代码，方便自己快速理解，也方便后续给老师或面试官做项目介绍。

---

## 1. 整体分层结构

当前评论模块遵循项目原有的 DDD 风格分层：

- `start` 层：Controller、ReqVO / RespVO、VO Convertor
- `application` 层：`CommentBizService`，负责用例编排和 BO 组装
- `domain` 层：`CommentDomainService`，负责核心业务规则、分片路由说明、缓存读写逻辑
- `infrastructure` 层：RepositoryImpl、Mapper、PO、Mapper XML，负责数据库访问和持久化实现

- `ssp-comment-center-start/src/main/java/com.ssp.comment/start/controller/comment/CommentController.java`

## 2. Controller / Service / Mapper / XML 怎么分布

### 2.1 Controller 层

当前 Controller 分成两个入口：

#### `CommentController`

负责评论主接口：

- `POST /api/comment/create`
- `POST /api/comment/delete`
- `POST /api/comment/edit`
- `POST /api/comment/pin`
- `GET /api/comment/list`
- `POST /api/comment/like`
- `POST /api/comment/unlike`
- `POST /api/comment/audit/callback`
- `GET /api/comment/hot`
- `GET /api/comment/my/list`

#### `ReplyController`

负责回复列表接口：

- `GET /api/reply/list`

这样拆分的原因是：

- 文档里回复列表接口口径就是 `/api/reply/list`
- 单独抽出 `ReplyController` 后，代码和技术文档一致

### 2.2 Service 层

#### `CommentBizService`

这是 application 层服务，负责：

- 承接 Controller 的调用
- 调 domain service
- 将领域实体转成 BO
- 再由 `CommentVOConvertor` 转成返回 VO

#### `CommentDomainService`

这是 domain 层核心服务，负责：

- 创建评论 / 回复
- 删除评论 / 回复
- 编辑评论 / 回复
- 置顶
- 评论列表 / 回复列表 / 热评列表
- 点赞 / 取消点赞
- 审核回调
- “我评论过哪些”查询
- 分片路由说明
- Redis 缓存读写逻辑

### 2.3 Mapper 与 XML

#### Mapper 接口

当前有 5 个 Mapper：

- `CommentMapper`
- `ReplyMapper`
- `CommentLikeMapper`
- `CommentAuditMapper`
- `UserCommentIndexMapper`

#### 对应 XML

路径：

- `ssp-comment-center-infrastructure/src/main/resources/mapper/comment/CommentMapper.xml`
- `ssp-comment-center-infrastructure/src/main/resources/mapper/comment/ReplyMapper.xml`
- `ssp-comment-center-infrastructure/src/main/resources/mapper/comment/CommentLikeMapper.xml`
- `ssp-comment-center-infrastructure/src/main/resources/mapper/comment/CommentAuditMapper.xml`
- `ssp-comment-center-infrastructure/src/main/resources/mapper/comment/UserCommentIndexMapper.xml`

说明：

- `Mapper.java` 只保留方法签名
- 具体 SQL 放到 `mapper/comment/*.xml`
- 这样和项目现有 `user` 模块风格保持一致

## 5. 分库分表逻辑在源码里怎么体现

### 5.1 路由类

路径：

- `ssp-comment-center-domain/src/main/java/com.ssp.comment/domain/comment/route/CommentShardRouter.java`

作用：

- 统一封装评论表和回复表的分片路由规则

当前规则：

- 评论表按 `comment_object_id` 路由
- 回复表按 `comment_id` 路由

### 5.2 在哪些业务方法里体现了路由

在 `CommentDomainService` 里已经显式调用了路由器，并加了注释说明：

- `createComment`
- `createReply`
- `queryCommentPage`
- `queryReplyPage`
- `queryMyComments`

### 5.3 现在的“分片逻辑体现”是怎么做的

当前代码里是：

1. 用 `CommentShardRouter` 计算逻辑路由结果
2. 记录日志、加注释说明这一步为什么要按这个键路由
3. Repository / Mapper 仍然面向逻辑表编码

也就是说：

- 现在是“源码层体现分片设计思路”
- 真正的物理分片路由仍然应该由后续 `ShardingSphere-JDBC / ShardingJDBC` 接管

这和技术文档的表达是一致的。

## 6. 缓存读写逻辑在源码里怎么体现

### 6.1 缓存主要放在哪一层

主要放在：

- `CommentDomainService`

原因：

- 缓存属于核心业务链路的一部分
- 点赞数、点赞状态、热评排序都和评论业务强相关
- 放在 domain service 里更方便统一说明“读缓存 / 写缓存 / 更新热榜”

### 6.2 当前已经体现的缓存种类

#### 1. 评论点赞数缓存

Key 模式：

- `comment:like:obj:{commentObjectId}`

结构：

- `Hash`

逻辑位置：

- `batchFillCommentLikeCount`
- `incrementCommentLikeCache`

#### 2. 回复点赞数缓存

Key 模式：

- `reply:like:obj:{commentObjectId}`

结构：

- `Hash`

逻辑位置：

- `batchFillReplyLikeCount`
- `incrementReplyLikeCache`

#### 3. 用户点赞状态缓存

Key 模式：

- `user:like:{userId}:target:{targetType}:{targetId}`

结构：

- `String / Bucket`

逻辑位置：

- `markUserLiked`
- `isUserLiked`

#### 4. 热评缓存

Key 模式：

- `comment:hot:obj:{commentObjectId}:type:{commentType}`

结构：

- `ZSet`

逻辑位置：

- `queryHotComments`
- `updateHotCommentScore`

### 6.3 哪些流程体现了“缓存读写”

- 评论列表查询：
  - 批量读评论点赞数缓存
  - 批量读回复点赞数缓存
- 点赞：
  - 写评论 / 回复点赞数缓存
  - 写用户点赞状态缓存
  - 更新热评缓存
- 取消点赞：
  - 回滚评论 / 回复点赞数缓存
  - 删除用户点赞状态缓存
  - 更新热评缓存
- 热评列表：
  - 优先读 ZSet
  - 未命中回源数据库
  - 再回填缓存

## 7. 为什么要单独加 `UserCommentIndex`

这是当前结构里一个很关键、也很值得讲的点。

### 7.1 背景

“我评论过哪些”属于用户维度反查。

但当前主表的分片键是：

- 评论表：`comment_object_id`
- 回复表：`comment_id`

这意味着如果直接按 `userId` 查评论表 / 回复表，会出现：

- 不命中主分片键
- 需要跨分片查询
- 查询成本高

### 7.2 解决方案

单独设计：

- `component_user_comment_index`

专门承接：

- “我评论过哪些”
- 以后也可以扩展“我回复过哪些”“我互动过哪些”

### 7.3 源码体现在哪

- Entity：
  - `UserCommentIndexEntity`
- PO：
  - `UserCommentIndexPO`
- Repository：
  - `UserCommentIndexRepository`
  - `UserCommentIndexRepositoryImpl`
- Mapper：
  - `UserCommentIndexMapper`
  - `UserCommentIndexMapper.xml`
- Domain：
  - `updateUserCommentIndex`
  - `queryMyComments`

## 8. 关键流程伪代码

下面这些伪代码适合你介绍项目时直接讲。

### 8.1 创建评论流程

```java
Controller.create(req):
    userId = UserContext.getCurrentUserId()
    bizService.create(req, userId)

BizService.create(...):
    if type == 1:
        domainService.createComment(...)
    else:
        domainService.createReply(...)

DomainService.createComment(...):
    校验参数
    根据 commentObjectId 计算分片路由
    组装 CommentEntity
    commentRepository.save()
    更新 user_comment_index
    返回结果
```

### 8.2 评论列表查询流程

```java
Controller.list(req):
    bizService.listComments(req, currentUserId)

BizService.listComments(...):
    domainService.queryCommentPage(...)
    转成 CommentListBO

DomainService.queryCommentPage(...):
    根据 commentObjectId 计算评论分片路由
    commentRepository.countByObject(...)
    commentRepository.queryPageByObject(...)
    从 Redis 批量读取评论点赞数
    replyRepository.queryByCommentIdsAndParent(commentIds, 0)
    从 Redis 批量读取回复点赞数
    按 commentId 分组 replies
    每条评论截取 topN 回复
    返回分页结果
```

### 8.3 点赞流程

```java
Controller.like(req):
    bizService.like(targetId, targetType, userId)

BizService.like(...):
    domainService.like(...)

DomainService.like(...):
    判断点赞记录是否已存在
    写 component_comment_like
    if 点赞评论:
        commentRepository.updateLikeCount(+1)
        更新 comment:like:obj:{objectId}
        更新 user:like:{userId}:target:{type}:{targetId}
        更新热评 ZSet
    else:
        replyRepository.updateLikeCount(+1)
        更新 reply:like:obj:{objectId}
        更新用户点赞状态缓存
    返回 liked = true
```

### 8.4 热评列表流程

```java
Controller.hot(req):
    bizService.listHotComments(...)

DomainService.queryHotComments(...):
    先读 Redis ZSet
    if 命中:
        根据 commentId 批量查评论详情
        按 ZSet 顺序组装
    else:
        commentRepository.queryHotPageByObject(...)
        回填 ZSet
    批量填充点赞数缓存
    返回分页结果
```

### 8.5 “我评论过哪些”流程

```java
Controller.myList(req):
    userId = UserContext.getCurrentUserId()
    bizService.listMyComments(userId, ...)

DomainService.queryMyComments(...):
    // 注意：这里不查评论主表和回复主表
    // 因为 userId 不命中主分片键
    直接查 component_user_comment_index
    按 latest_time 倒序分页
    返回对象维度列表
```

## 9. 你给别人介绍时可以怎么讲

可以直接按下面这个顺序讲：

1. **先讲分层**
   - 我这个评论模块不是只写了 Controller，而是按项目原有 DDD 分层补了四层
   - `Controller -> BizService -> DomainService -> RepositoryImpl -> Mapper/XML`

2. **再讲接口**
   - 一共实现了文档里的 11 个接口
   - 评论主接口在 `CommentController`
   - 回复列表单独在 `ReplyController`

3. **再讲亮点**
   - 评论表按 `comment_object_id` 路由
   - 回复表按 `comment_id` 路由
   - “我评论过哪些”因为不命中主分片键，所以单独设计了 `user_comment_index`
   - 点赞和热评走 Redis，已经在 domain service 里体现了缓存读写逻辑

4. **最后讲流程**
   - 创建评论
   - 评论列表
   - 点赞
   - 热评
   - 我评论过哪些

这样介绍下来会比较完整，也比较符合老师想听的“源码链路 + 设计思路 + 关键亮点”。
