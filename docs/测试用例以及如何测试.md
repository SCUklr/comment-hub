# 测试用例以及如何测试

> 本文档记录 ssp-comment-center 评论中心全部 API 接口的测试方法，包含 curl 命令、Postman/Apifox 配置步骤、字段说明、断言建议及踩坑记录。  
> 适合豆包、ChatGPT、Cursor、Claude 等 LLM 快速阅读与检索。

---

## 一、接口总览

| 分类 | 接口 | 方法 | URL | 需登录 |
|------|------|------|-----|--------|
| 评论 | 创建评论 | `POST` | `/api/comment/create` | ✅ |
| 评论 | 删除评论 | `POST` | `/api/comment/delete` | ✅ |
| 评论 | 编辑评论 | `POST` | `/api/comment/edit` | ✅ |
| 评论 | 置顶/取消置顶 | `POST` | `/api/comment/pin` | ✅ |
| 评论 | 评论列表 | `GET` | `/api/comment/list` | ❌ |
| 评论 | 热评列表 | `GET` | `/api/comment/hot` | ❌ |
| 评论 | 点赞 | `POST` | `/api/comment/like` | ✅ |
| 评论 | 取消点赞 | `POST` | `/api/comment/unlike` | ✅ |
| 评论 | 我的评论 | `GET` | `/api/comment/my/list` | ✅ |
| 评论 | 审核回调 | `POST` | `/api/comment/audit/callback` | ❌ |
| 回复 | 回复列表 | `GET` | `/api/reply/list` | ❌ |

> **认证方式**：Header 携带 `X-User-Id` 模拟登录用户（纯数字，如 `X-User-Id: 1`）。  
> 带 `@LoginRequired` 的接口缺失此 Header 会返回 `401 "请先登录"`。

## 二、curl 快速测试命令

以下命令可直接在终端复制粘贴执行。**注意替换返回的 ID**。

### 1. 创建一级评论

```bash
curl -s -X POST http://localhost:8080/api/comment/create \
  -H "Content-Type: application/json" \
  -H "X-User-Id: 1" \
  -d '{
    "type": 1,
    "commentObjectId": 10001,
    "commentType": 1,
    "content": "这是一条测试评论"
  }'
```

**字段说明：**
- `type`: `1` = 创建一级评论，`2` = 创建回复
- `commentObjectId`: 被评论的对象 ID（如帖子 ID、视频 ID）
- `commentType`: 业务类型（如 `1`=帖子、`2`=视频，用于 ShardingSphere 分库）
- `content`: 评论内容（必填）

**响应示例：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "type": 1,
    "id": 720209260377591808,
    "commentObjectId": 10001,
    "commentType": 1,
    "content": "这是一条测试评论",
    "images": "[]",
    "createTime": "2026-06-11T17:34:28.516004",
    "updateTime": "2026-06-11T17:34:28.516007"
  }
}
```

> **记下返回的 `id`**，后续回复、点赞、删除都需要用到。

---

### 2. 回复评论

```bash
curl -s -X POST http://localhost:8080/api/comment/create \
  -H "Content-Type: application/json" \
  -H "X-User-Id: 2" \
  -d '{
    "type": 2,
    "commentId": 720209260377591808,
    "content": "这是一条回复"
  }'
```

**字段说明：**
- `type`: `2` = 回复
- `commentId`: 上一级评论的 ID（上一步返回的 `id`）
- `parentId`: 楼中楼回复时填上级回复 ID，一级回复可不填或填 `0`
- `beRepliedUserId`: 被回复人的用户 ID（可选）


**字段说明：**
- `commentObjectId` + `commentType`: 定位评论对象（必填）
- `page` / `pageSize`: 分页，默认 `1` / `20`
- `topReplyLimit`: 每条评论下展示几条热回复，默认 `3`

每个接口的 Tests 中建议包含：

```javascript
pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);

pm.test("Business code is 200", function () {
    var json = pm.response.json();
    pm.expect(json.code).to.eql(200);
});

pm.test("Message is success", function () {
    var json = pm.response.json();
    pm.expect(json.message).to.eql("success");
});
```

## 六、验证 Spring Event 异步监听器

执行点赞后，查看应用日志：

```bash
tail -20 /tmp/springboot.log
```

应出现类似以下内容：

```
[comment-event-1] [HotScoreUpdate] commentId=..., newLikeCount=1, hotScore=...
```

- 热评分数更新、缓存刷新由异步监听器在独立线程池中处理
- 线程名前缀为 `comment-event-`

## 七、常见问题

### Q1：Apifox / Postman 返回 401 "请先登录"

**原因**：`X-User-Id` Header 没有正确传递到后端。  
看拦截器源码 `UserContextInterceptor.java`：

```java
String userIdStr = request.getHeader("X-User-Id");
if (userIdStr != null && !userIdStr.isEmpty()) {
    UserContext.setCurrentUserId(Integer.valueOf(userIdStr));
}
```

如果 `X-User-Id` 缺失、为空、或不是纯数字，`@LoginRequired` 接口就会返回 401。

**解决**：
- 在 **Header 参数** 中添加 `X-User-Id: 1`（纯数字，不要带引号）
- **不要**把 `X-User-Id` 放到 Body 或 Query 里
- Header 参数名大小写敏感，必须是 `X-User-Id`

---

### Q2：回复评论返回 500 "评论不存在"

**原因**：父评论已被删除（`is_delete=1`）。  
看代码 `CommentDomainService.java`：

```java
CommentEntity parentComment = commentRepository.queryById(commentId);
if (parentComment == null || Objects.equals(parentComment.getIsDelete(), DELETE_MARK)) {
    throw new BizException("评论不存在");
}
```

**解决**：先用创建评论接口生成一个新的评论 ID，再用新 ID 去回复。

---

### Q3：`commentObjectId` 是否必须真实存在？

**不需要。**

这个项目的定位是**通用评论中心**，`commentObjectId` 是外键，指向业务系统（如帖子、视频）的 ID，但：
- 数据库表**没有外键约束**
- 代码中**没有任何校验**去确认 `10001` 在业务系统里是否真实存在
- `commentType` 只是用于 ShardingSphere 分库分片的路由键

所以 `commentObjectId=10001` 只是一个**测试用的虚拟 ID**，完全合法。

---

### Q4：返回 500 但日志看不到详细错误

**解决**：查看 Spring Boot 日志文件：

```bash
tail -50 /tmp/springboot.log
```

搜索 `ERROR`、`BizException`、`Caused by` 关键字定位问题。

---

### Q5：点赞后查询列表 likeCount 没有变化

**原因**：列表查询走的是 Redis 缓存，异步监听器可能还没执行完。  
**解决**：等待 1~2 秒后重新查询，或查看日志确认监听器已消费事件。

## 八、响应格式说明

所有接口统一返回：

```json
{
  "code": 200,
  "message": "success",
  "data": { ... }
}
```

- `code=200`：业务成功
- `code=401`：未登录（缺少 `X-User-Id`）
- `code=500`：业务异常（如重复点赞、评论不存在等）
- `code` 非 200 时，`message` 会携带具体错误信息
