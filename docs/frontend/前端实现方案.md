## 二、核心组件设计（第 2 步）

### 2.1 `UserSwitcher` — 用户身份切换

- 页面顶部固定栏，提供 `InputNumber` 输入用户 ID。
- 切换后写入 `localStorage`，并通过 `React Context` 广播到全组件。
- 所有 API 请求拦截器自动从 Context 读取并注入 `X-User-Id` Header。

### 2.2 `CommentList` — 评论列表 + 分页

- 使用 Ant Design `List` + `Pagination`。
- 支持排序切换：`timeDesc`（默认）、`timeAsc`、`hot`（调热评接口）。
- 每条数据渲染 `CommentItem`，支持展开/收起回复。

### 2.3 `CommentItem` — 单条评论卡片

- 使用 Ant Design `Comment` 组件（头像、作者、时间、内容、操作栏）。
- 操作栏：点赞按钮、回复按钮。
- 点击「回复」展开嵌套的 `ReplyTree`。
- 内容区支持纯文本展示（后续可扩展 Markdown / 图片）。

### 2.4 `ReplyTree` — 楼中楼回复树

- 树形结构展示：根回复 → 二级回复（最多展示两层，更深折叠）。
- 每条回复同样使用 `Comment` 组件，缩进通过自定义 CSS 或 `Comment` 的嵌套属性实现。
- 支持「回复此回复」的输入框（内嵌小型 `Form`）。

### 2.5 `LikeButton` — 点赞按钮

- 封装 Ant Design `Button`（带 `heart` Icon）。
- 状态：已点赞（红色实心）/ 未点赞（灰色空心）。
- 点击触发 `useLike` Hook，乐观更新本地计数 + 调接口，失败回滚。
- 可选：点赞动画（CSS `scale` 脉冲）。

### 2.6 `HotCommentList` — 热评侧边栏

- 调用 `GET /api/comments/hot` 接口，展示 Top-N 热评。
- 与主列表共用 `CommentItem` 组件，减少重复代码。

## 四、状态管理方案（第 4 步）

当前阶段采用 **React Context + useReducer**，避免 Redux 的样板代码。

### 4.1 `UserContext`

- 存储 `currentUserId`（从 `localStorage` 初始化）。
- 提供 `setUserId` 方法，切换后持久化到 `localStorage`。

### 4.2 组件级状态（useState / useReducer）

- `CommentList`：分页、排序、列表数据、加载态。
- `ReplyTree`：展开/折叠、回复列表、提交中状态。
- `LikeButton`：本地点赞数、本地是否已点赞（乐观更新）。

> 若后续状态复杂度上升，可平滑迁移至 Zustand 或 Redux Toolkit。

## 五、与后端联调要点（第 5 步）

### 5.1 CORS 配置

- 后端 `CorsConfig` 已允许 `http://localhost:5173`（Vite 默认端口）。
- 生产环境通过 Nginx 反向代理，或追加前端域名到 `CorsConfig`。

### 5.2 接口契约对齐

- 前端 `types/comment.ts` 中的类型定义必须与后端《接口契约.md》保持同步。
- 变更时建议先改契约文档，再同步前后端代码。

### 5.3 分页与热评

- 主列表分页：`GET /api/comments?page=1&size=10&sort=timeDesc`。
- 热评：独立调用 `GET /api/comments/hot?objectId=xxx&limit=10`，不占用主分页。
- 排序切换时重置 `page=1`。

## 七、与旧方案对比（为什么要改）

| 维度 | 旧方案 A（纯静态 HTML） | 新方案 B（React + TS + Ant Design） |
|------|------------------------|-------------------------------------|
| 组件化 | ❌ 无，HTML 复制粘贴 | ✅ 复用 CommentItem、ReplyTree |
| 类型安全 | ❌ 无 | ✅ TypeScript 接口契约对齐 |
| UI 一致性 | ❌ 手写 CSS 易偏差 | ✅ Ant Design 设计规范统一 |
| 状态管理 | ❌ 全局变量 | ✅ React Context + Hooks |
| 扩展性 | ❌ 难以扩展 | ✅ 可平滑引入 React Query、路由、图片上传 |
| 面试展示 | ⚠️ 简单 | ✅ 更贴近企业级实践，与简历技术栈对齐 |
| 复杂度 | ✅ 零构建 | ⚠️ 需 Node 环境（但 Vite 已极简化） |
